# Выбор парадигм и языков программирования

## Задача 1. Обработка больших данных в реальном времени

* **Парадигма:** Императивная / Процедурная (с ориентацией на данные — *Data-Oriented Design*).
* **Язык программирования:** C++ (как современная альтернатива — Rust).
* **Обоснование:**
  1. **Огромный поток данных:** При характеристиках $4096 \times 4096 \times 2\text{ байта} \times 100\text{ кадров/с}$ поток составляет $\approx 3.35\text{ ГБ/с}$. Требуется прямое управление памятью без накладных расходов на аллокации и структуры объектов.
  2. **Отсутствие пауз GC:** В системах реального времени (бюджет на кадр — 10 мс) и режиме работы 24/7 сборщики мусора (Garbage Collector) неприменимы из-за непредсказуемых пауз *Stop-The-World*, которые приводят к переполнению буферов и потере кадров.
  3. **Аппаратная оптимизация:** C++ позволяет эффективно задействовать кэш процессора, применять векторные инструкции (**SIMD / AVX**) для математической фильтрации изображений, а также напрямую интегрироваться с ускорителями вычислений (CUDA, OpenCL).

## Задача 2. Прототип ML-сервиса для прогноза погодных условий

* **Парадигма:** Мультипарадигмальная (процедурный пайплайн обработки данных + функциональные преобразования + элементы ООП).
* **Язык программирования:** Python.
* **Обоснование:**
  1. **Минимальный Time-to-Market:** Жесткий срок в 2 недели на MVP требует максимальной скорости разработки. Высокоуровневый синтаксис Python и динамическая типизация позволяют быстро писать и модифицировать код.
  2. **Богатая экосистема ML:** Наличие зрелых готовых библиотек (scikit-learn, XGBoost, PyTorch, pandas), в которых вычислительно тяжелые алгоритмы уже реализованы на C/Fortran.
  3. **Некритичность к задержкам:** Прогноз выполняется 1 раз в сутки, поэтому оверхед интерпретатора на скорость вычислений не оказывает негативного влияния на бизнес-требования.
  4. **Легкость итераций:** Возможность быстро менять модели, экспериментировать с признаками и перенастраивать пайплайн без длительной перекомпиляции проекта.

## Задача 3. Интерактивный UI для торгового терминала

* **Парадигма:** Реактивная (Функционально-реактивное программирование / *FRP*) и компонентно-декларативная.
* **Язык программирования:** TypeScript.
* **Обоснование:**
  1. **Реактивность сложных потоков данных:** Потоки котировок из WebSocket и события пользователя естественно представляются в виде реактивных потоков (RxJS, Signals). Изменение цены в одном потоке автоматически обновляет зависимые виджеты без запутанных мутаций глобального состояния.
  2. **Производительность (< 16 мс):** Бюджет 16 мс соответствует частоте 60 кадров/с в браузере. Гранулярные реактивные обновления позволяют избегать полного рендеринга страницы и укладываться во фреймрейт.
  3. **Статическая типизация и надежность:** TypeScript предотвращает ошибки времени выполнения при интеграции сложных DTO из WebSocket/REST API.
  4. **Тестируемость:** Декларативное разделение UI на независимые чистые компоненты и вынесение бизнес-логики в чистые функции/селекторы обеспечивают простое покрытие Unit-тестами.

## Задача 4. Прошивка для устройства регистрации температуры

* **Парадигма:** Процедурная / Императивная (структурное программирование, модель конечных автоматов — *FSM*).
* **Язык программирования:** C (Си).
* **Обоснование:**
  1. **Жесткие ресурсные ограничения:** Доступно всего 256KB Flash и 32KB RAM. Си компилируется в компактный машинный код без скрытого оверхеда на виртуальные таблицы классов (`vtable`), RTTI или раскрутку исключений.
  2. **Прямой доступ к оборудованию:** Нативная работа с указателями на физические адреса регистров периферии (GPIO, ADC, UART) с использованием квалификатора `volatile`.
  3. **Детерминизм и энергоэффективность:** Предсказуемое время исполнения инструкций (hard real-time) и возможность полного контроля над энергопотреблением микроконтроллера (перевод ядра и периферии в режимы Sleep / Deep Sleep для экономии батареи).
  4. **Абсолютная переносимость:** Компиляторы языка C (GCC, Clang, IAR, Keil) существуют для любых архитектур микроконтроллеров (ARM Cortex-M, RISC-V, AVR, ESP).
